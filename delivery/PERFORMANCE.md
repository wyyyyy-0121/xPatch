当前 CPU 基线队列已完成。两 worker 的预载加前向融合方案只改善约 1.76%，未启用并发；完整反向融合通过减少计算及启动开销提速。实验全局仍最多 22 个逻辑线程，显存预载最多 1 GiB 并保留至少 1 GiB 空闲。原研究与执行锁保持完整，新追加锁延续原签名和预算。当前只放行 `development`；新实验仍须单独验收。上一份性能报告按原字节保存在 `delivery/amendments/performance_before_throughput.json`。

以下记录为首次诊断和上一轮 CUDA graph 验收的历史说明；当前数值以本页新增说明、`delivery/performance.json` 和 `delivery/RUN_RISK.md` 为准。

2026-11-03 对正在运行的搜索进行诊断。诊断只读取任务状态、参数、样本数和耗时，没有查看正式预测分数或据此调参。机器可读证据索引为 `delivery/performance.json`。

后续已完成完整 CUDA graph 执行加速验收：192 项配置/信息集/批量检查、六组训练续训检查、安装后双向恢复、最大规模预测和 30 轮持续运行通过。最大规模训练一轮约快 3.74 倍，完整评价预测约快 4.36 倍。当前结果和中止风险见 `delivery/RUN_RISK.md`，执行修订见 `delivery/rv30_acceleration_lock.json`。以下初次诊断及原耗时情景保留为历史；对应原报告另存 `delivery/amendments/performance_before_acceleration.json`。

## 本次耗时原因

训练一直在完成任务。CPU 模型已结束，GPU 队列仍有大量任务。`80/120` 是模型组计数，不能解释为耗时已完成三分之二：未完成的 xPatch 组还包含 15/30 轮 halving、多种子复核及外层拟合。

40 秒进程采样中，GPU worker 实际消耗约 0.84 个 CPU 核心，三个 CPU worker 均空闲；进程无实际磁盘读取，写入约 6.52 MiB，内存、I/O 与 CPU 压力均未出现持续等待，swap 使用为零。另一个 32 秒窗口的 16 次 GPU 采样利用率为 38–52%，均值 46%，显存约 3.54 GiB / 12 GiB，温度 49–51℃。这些窗口支持资源尚未充分使用；不能据此证明所有时段都不存在硬件或系统因素。

截至初次耗时汇总，已完成 GPU 任务共约 10.56 小时，其中 DEMA 约 9.02 小时，EMA 约 0.86 小时，Chronos-2 约 0.69 小时。DEMA 占约 85%。不同配置存在其他参数差异，因此随后进行了固定网络尺寸的隔离对照。

## 隔离吞吐测试

先停止自动最终化等待器，再对原 driver 发送 SIGINT，保存原日志、任务回执与每轮检查点；确认所有训练 worker 已退出后才使用 GPU。测试约 78 秒，结束后核验原签名并恢复同一 `development` 搜索及其自动最终化等待器。诊断按 22 个分配 CPU 和全程 GPU 墙钟时间保守计入原签名预算，记录在 `delivery/amendments/performance_diagnostic.json`。

全部使用 2023 年以前的数据：29,105 个训练样本、6,740 个完整校准起点、700 个评价起点。固定 batch=128、patch=32 及其余网络参数，对两个信息集、64/512 回看与 EMA/DEMA 跑完整一轮；额外以 4→18→4 线程重复最长 DEMA。10 个任务全部完成，测试模型只用于性能测量。

| 市场信息集、512 回看 | 训练一轮 | 完整校准预测 |
|---|---:|---:|
| EMA，4 线程 | 1.59 秒 | 0.17 秒 |
| DEMA，4 线程 | 11.04 秒 | 2.40 秒 |
| DEMA，18 线程 | 11.06 秒 | 2.60 秒 |
| DEMA，再次 4 线程 | 10.74 秒 | 2.43 秒 |

增加线程没有观察到吞吐提升。这只是短时配对对照，不能把微小差异解释为确定的性能退化。第一项冷启动任务单列保留在原始记录中，未用它夸大对照效果。

相同网络尺寸的单批次 profiler 中，EMA 为 113 次 `cudaLaunchKernel`，DEMA 为 5,233 次。DEMA 的 CPU 自耗时约 41.43 ms，其中内核启动约 23.45 ms。原 DEMA 逐时间步执行 Python 递推，产生大量很小的 GPU 操作；增加 BLAS/PyTorch 线程无法把这一递推自动变成并行任务。完整输入与标签构造耗时远小于长 DEMA 训练和预测。本次因此将串行递推和内核启动开销定位为主要性能瓶颈，没有修改原拟合实现或声称已经提速。

## 耗时估算的适用范围

`delivery/performance.json` 使用已完成的初筛任务，按配置、信息集及训练日数估算尚未完成的初筛，再对后续保留配置的计算成本作情景分析。未读取配置排名或预测分数。

初筛 xPatch 剩余约 7.7 小时、Chronos 含估计外层约 1 小时；后续训练若跑满各阶段轮数，保留便宜、中等、昂贵配置的剩余搜索情景分别约 16、27、186 小时。它们是计算成本情景，**不是置信区间、最短/最长期限或交付承诺**；早停可缩短，较大训练集与实际保留配置会改变耗时，独立回放、统计复核和条件确认还需额外时间。240 GPU 小时冻结预算不变。

## 后续启动规则

当前测量允许原签名、原实现、原搜索空间的 `development` 恢复。当前报告的 `new_experiment_ready=false`：本次仅一轮、训练样本仍小于后期最大折，因此不能充当下一项长实验的完整验收。

新增实验必须先完成：

1. 在首次外折以前的数据上覆盖最大计划样本数、短/长回看、EMA/DEMA、两个信息集和完整校准/评价预测。若用重复早期数据模拟最大规模，明确标为性能专用复制，绝不进入研究结果。
2. 测完整代表训练/halving 续训及恢复，分解预处理、传输与内核调用、训练、校准预测、保存耗时；保留 CPU/GPU 和内存/显存峰值。比较线程配额后再选配置，实验全局上限仍为 22 逻辑线程。
3. 按所有搜索阶段、种子、独立验证及条件阶段估算耗时范围，并核对剩余预算、数据/代码/依赖与硬件身份。实现优化要另存计算修订和等价性证据，不能静默覆盖研究冻结。
4. 更新匹配的性能证据，再通过 `scripts/start_rv30_checked.py`。证据缺失、变动或新实验尚未合格时，该入口返回非零状态并拒绝启动。底层 finance CLI 继续核验研究冻结和独占运行锁。

性能检查不新增产品版本目录。细节、原始采样与 profiler 均通过固定证据索引追溯；助手按用户最新要求每 60 分钟检查一次。
