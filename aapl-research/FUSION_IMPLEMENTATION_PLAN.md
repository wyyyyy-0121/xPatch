# AAPL 分钟预测：基础模型与多专家神经融合研发计划书

日期：2026-11-05。工作目录：`/home/ayaka/wslcode/aapl-research`。

**交付目标：开发一个可训练、可复现、可本地推理的 AAPL 分钟预测融合系统，并用保留数据判断它是否优于充分调参的单模型、简单融合与零收益。** 主任务仍为未来 12 分钟累计对数收益。研究重点是多股票迁移、量价信息与基础模型表示的结合，以及随市场状态变化的专家权重。

本文是下一阶段的实施方案。它不表示已经取得预测改善，也不启动训练、云端租赁或最终检验。现有 `FUSION_PLAN.md`、`outputs/fusion/protocol.json` 及实现保留原身份；执行本计划前须核对已有任务，建立新的范围清单，避免用新规则解释旧结果。后续沿用本文文件名，配置与实验记录使用 trial ID，不为小改动增加项目大版本。

**1. 当前证据与需要解决的问题**

上一轮在 AAPL 下午样本上完成了零收益、Ridge、LightGBM、xPatch、PatchTST、Chronos-2 冻结和 LoRA 的比较。所有候选在旧 D 块都未优于零收益。开发验证的最佳改善不足 1%，在旧 D 块未保持，因此目前不能声称某个模型已经有效。

已有 `fusion/` 包包含特征、专家、融合头和推理实现。工程准入记录验证了部分因果性、批次不变性及保存加载一致性；这只能说明部分实现行为符合要求。现有小规模融合继续作为参考实现，不能替代本文的全天任务、跨股票迁移和最终效果验收。

本轮检验三个假设：

| 假设 | 开发方法 | 必须回答的问题 |
|---|---|---|
| 单一 AAPL 历史不足以训练稳定表示 | 多股票共享训练，再对 AAPL 适配 | 同结构同预算下，联合训练是否优于只训练 AAPL？ |
| 不同方法在市场状态中具有互补性 | 状态门控多专家，包含零收益专家 | 门控是否优于静态权重，以及同参数量普通融合网络？ |
| 预训练表示能补足本地量价模型 | Chronos-2 编码表示与 xPatch 分支融合 | 去掉基础模型后，收益是否消失？LoRA 是否带来额外收益？ |

计划中的“大模型”指复用已有预训练基础模型并进行适配。首选已核对身份的约 120M 参数 Chronos-2。先冻结骨干、训练小模块，再有条件解冻 LoRA；最终报告总参数量、可训练参数量和计算成本。从头训练十亿参数金融模型超出本计划的数据与预算。

**2. 神经网络如何应用**

xPatch、PatchTST、Chronos 都属于神经网络。本轮拟开发的部分是联合预测结构、训练方法与部署系统。

模型接收已经完成的分钟柱，分成以下支路：

- **AAPL 局部时序支路：** xPatch 编码器处理收益、振幅、成交量等多尺度历史，保留短期结构和分解信息。
- **基础模型支路：** Chronos-2 编码器提取相同历史的预训练表示。先冻结骨干并训练可学习投影，不把未经验证的随机压缩当成唯一实现；再比较 LoRA 适配。
- **市场背景支路：** 小型因果 TCN 或 Transformer 编码同一时刻已可用的 SPY、QQQ 及固定同业股票历史，学习市场共同变化。两种编码器只在固定开发搜索中比较。
- **已有专家支路：** Ridge、LightGBM、xPatch、PatchTST 的时间样本外预测作为低维输入。Chronos 原生预测只有通过开发准入后才进入专家集合；Chronos 编码表示的实验仍保留。
- **融合头：** 小型 MLP 读取上述表示、时刻、过去波动、趋势及专家分歧，生成专家权重、预测收缩强度和小幅残差修正。

初始网络规模控制为：投影维度 64 或 128，门控隐藏维度 32 或 64、两层 MLP，新增可训练参数目标不超过 5M。跨股票共享权重，股票 ID 使用小型 embedding。LoRA rank 搜索 8 或 16，实际挂载层以已安装模型结构为准，输出可训练参数清单。

设各专家的收益预测为 `p_k`，过去数据估计的未来 12 分钟尺度为 `sigma_12`。候选融合形式为：

```text
w = softmax(gate(表示、市场状态、专家分歧))
p_0 = 0
prediction = sigmoid(a) * sum(w_k * p_k)
             + c * sigma_12 * tanh(residual_head(联合表示))
```

`sigma_12` 只能使用预测起点之前的收益，缩放规则在训练段拟合；`c` 从预先列出的集合 `{0, 0.25, 0.5}` 中选择。训练中约束残差与权重变化，防止融合头放大噪声。保留零收益和收缩机制，让模型在缺乏证据时输出接近零。

这里的门控网络借鉴 mixture-of-experts 思路，但首版同时计算少量专家。报告实际推理成本，不宣称具有稀疏大模型的计算优势。树模型以保存的预测接入，不对树反向传播；神经网络部分可以联合训练。

专家输出必须来自时间样本外推理。新增局部和市场分支在当前折训练段内与融合头共同训练，验证时冻结；不得把在验证标签上训练过的隐藏表示再交给融合头。基础模型的跨序列分组仅允许同一预测起点内、当时可用的变量交流，不同历史起点不得因批量组装而交换信息。

**3. 数据范围与全天预测定义**

主任务覆盖正常交易时段中有完整未来 12 分钟标签的起点。取消“同日必须先积累 240 分钟”这一条件，使用前一交易日已完成的历史补足开盘窗口。以柱结束时刻作为统一决策时间：正常完整交易日最早可在 09:31 ET 使用第一根完成柱，最晚在 15:48 ET 预测至 16:00 ET。按交易所日历处理提前收盘；不跨收盘构造未来标签。

历史窗口候选为 48、96、240 个已完成的正常时段分钟柱。跨夜边界设置会话标记，分别表示隔夜跳空与日内收益；不能把两个交易日相邻的记录伪装成连续一分钟，也不生成虚假的夜间柱。最长窗口不足时统一排除相应起点，所有主比较使用相同合格起点。

数据从已有可用的 2021 年开始核对，覆盖至开发边界；增加更早历史须先验证同源数据覆盖。不能为节省时间把正式训练默认为仅使用 2023 年以后。所有模型共享原始字段与时间边界；原生输入受限的模型额外提供同信息集监督基线，区分算法效果与新增输入效果。

主输入包括已完成柱的 OHLCV、分钟内振幅、实体、过去收益、过去波动、时刻及会话状态。价格采用因果收益或相对价格表示，成交量采用训练段拟合的 `log1p` 与时刻季节性缩放。股票拆分、异常柱、缺失分钟及停牌单独处理；不得用未来价格反向修正已经构造的历史特征。

多股票联合训练作为本轮推荐主线，固定便利样本为：

```text
AAPL, MSFT, AMZN, GOOGL, META, NVDA, AMD, INTC,
JPM, BAC, XOM, CVX, WMT, COST, JNJ, UNH
```

SPY、QQQ 用作背景输入，不计入股票迁移的主结果。上述名单按本次研究目的固定，不能看到验证收益后换股；它具有当前存续与大盘股选择偏差，结论限于该样本。缺少历史的股票依据预先固定的数据覆盖规则排除并披露，不补选表现好的替代股票。

共同训练按股票和交易日均衡采样，避免 AAPL 或高波动股票主导训练。区分两种作用：其他股票的历史增加训练样本，预测当时已完成的市场柱提供背景信息。需要通过分开的消融判断各自贡献。

先核对免费 Alpaca 历史分钟数据的实际覆盖和下载限额，按供应商允许速率执行。云端仅传输获许可的开发数据、代码与权重。凭据、本地个人信息和保留检验数据不上传。

**6. 调参方案：先固定范围，再分配算力**

主目标始终是原始收益 MSE。允许比较尺度归一化训练损失，主评分仍还原为原始收益，防止更换评分口径得到表面改善。

| 搜索组 | 起始配置数 | 搜索范围与晋级 |
|---|---:|---|
| 同信息集单模型 | LightGBM 24、xPatch 16、PatchTST 16 | 复用旧优胜配置作起点，但全天多变量数据必须重新校准；学习率、正则、窗口与损失进入固定清单 |
| 简单融合 | 12 | 非负 Ridge/凸组合/收缩，正则与收缩系数固定网格；按时间向前验证 |
| 冻结骨干神经融合 | 24 | 窗口、投影维度、门控宽度、学习率、dropout、weight decay、残差幅度、原始/尺度化损失 |
| 联合训练与 AAPL 适配 | 8 对配对配置 | 仅 AAPL 与多股票共享训练；相同结构及预定更新预算；适配学习率与共享训练权重 |
| LoRA 神经融合 | 8 | rank 8/16、两档骨干学习率及适配层；固定骨干冻结对照，不默认为全参数微调 |

神经模型使用固定顺序的 successive halving：起始配置运行完整预算的 10%，排名前 1/3 运行到 30%，前 2 个运行到 100%。数据顺序、最大更新次数与学习率计划对晋级作业保持连续，不能反复重启挑最好的随机轨迹。小预算排序可能错过收敛较慢的方法，需记录这一限制。

F2 根据吞吐确定各模型的 100% 更新预算和早停耐心值；F2 不读取正式验证分数。随后一次生成 `search_manifest.json`，固定试验数、采样种子、更新数与淘汰规则，才允许开始 F3—F5。上表给出最大搜索范围；若时间投影超限，按后文顺序削减并在产生新验证分数前锁定。

最终两个候选按种子 2026、2027、2028 复核。系统若实际部署为三种子均值预测，验证和最终检验也以该均值系统评分，并另报各种子结果；不混用“种子平均损失”和“均值预测损失”。

旧专家超参已经受历史验证选择影响，其重新生成的历史样本外预测用于开发，不构成这些配置在历史当时已可选用的证明。后续最终检验只使用冻结的训练流程。

**7. 必须完成的机制对照**

最优结构在相同数据、种子、训练预算与搜索机会下完成以下对照。移除模块后从头训练，不能只在推理时关闭分支。

| 对照 | 目的 |
|---|---|
| 全系统与零收益、最强单模型、静态融合 | 检查实际增量，避免只超越弱基线 |
| 带门控与参数量相近的普通拼接 MLP | 判断收益来自状态分配还是增加参数 |
| 含基础表示与移除基础表示 | 判断 Chronos-2 表示是否有独立贡献 |
| 预训练骨干与同结构随机初始化骨干 | 区分预训练和网络容量；随机初始化可能收敛较慢，按同预算解释 |
| 冻结骨干与 LoRA | 判断适配价值，比较各自搜索后的最佳配置 |
| AAPL 单股训练与多股训练再适配 | 判断跨股票样本的贡献 |
| 有/无同刻市场背景 | 区分跨股票训练与新增市场输入的贡献 |
| close-only 与共同 OHLCV 信息集 | 区分输入改善和架构改善 |

基础模型注意力、门控权重和表示图只用作描述。机制证据来自配对对照，不能单凭一张权重热图声称识别了经济因果。

**8. CPU/GPU 性能与预算**

本地总上限为 22 个逻辑线程。沿用旧观察服务预留 4 线程，新研究最多 18 线程；Windows 保留的 10 线程不能借用。CPU 亲和性和线程池统一管理，不让每个作业各申请 18 线程。初始分配建议 GPU 数据与训练进程 6、LightGBM 8、数据与写盘 4，实际按吞吐调整，合计不超限。

GPU 训练同时推进 CPU 树模型和已完成分片的特征准备。单张 GPU 默认运行一个训练作业，仅当并发实测缩短总完工时间、且峰值资源通过时增加并发。记录吞吐、单作业耗时和总完工时间；不以 CPU/GPU 百分比作为唯一优化目标。

F2 至少完成：

1. 同一训练片段、相同更新步数比较原始执行与优化执行；覆盖最大窗口、最大批量和多股票批次。
2. 候选优化包括预生成因果特征、内存映射、冻结编码器缓存、批量推理、支持时使用 BF16、fused optimizer。`torch.compile` 和额外并发只有实测回本才启用。
3. 骨干固定时才复用表示缓存；LoRA 或编码器权重改变后禁止复用旧表示。缓存键包括权重、预处理、股票、时间边界及代码身份。
4. 连续最大形状运行至少 15 分钟，测峰值内存、显存、吞吐、温度或降频信息（能读取时）、检查点恢复及数值偏差；精度改变须通过有限性、损失与短程预测误差检查。
5. 以端到端实测估算全部折、配置、种子、OOF 重训和机制对照，加入 50% 余量。超过预算时先缩减计划，不能先运行再解释超时。

本轮按一张 GPU 计：**正式计算目标墙钟不超过 24 小时，含性能试跑的总 GPU 预留不超过 24 卡小时**。环境安装、网络下载及人工等待单列，不能把它们隐藏在 24 小时承诺中。多卡时同时报告墙钟与卡小时，不能将四卡一天写成 24 GPU 小时。

| 计算包 | 含余量的上限 |
|---|---:|
| 性能准入与资源测量 | 1 GPU 小时 |
| 季度 OOF、冻结表示与单模型适配 | 5 GPU 小时 |
| 神经融合与多股票训练搜索 | 7 GPU 小时 |
| LoRA 晋级、种子复核与消融 | 6 GPU 小时 |
| 最终重训、一次检验及推理验收 | 3 GPU 小时 |
| 故障与未预见开销 | 2 GPU 小时 |
| 合计 | 24 GPU 小时 |

若投影超限，在看新验证结果前依次：削减网络宽度候选；减少起始配置数并保留配对消融；只对晋级配置计算昂贵基础表示；将 LoRA 限制为两组预定配置。不得削掉三个月保留集、改用随机切分，或用缺少对照的训练替代最终验收。

本地单作业 RSS 初始上限 8 GiB、系统可用内存至少 4 GiB，显存使用不超过设备的 85%；若多股票缓存无法满足，改分片与内存映射。保留检查点、预测和统计即可复算主结论；冗余缓存按清单删除。

云端建议由用户选择单卡 A100/H100 80GB 或同等级有足够显存的设备，先做 15 分钟实测再确定租用时长。以上 24 小时是性能准入门槛，不是未测硬件上的保证。租赁、支付、供应商数据许可确认由用户处理；本地准备隔离环境、版本锁定和训练包。启动脚本支持本地/云端相同配置，最终检验留在本地。

**9. 结果验收与停止规则**

研究验收分两层，避免把能运行写成有效。

**工程交付：** 数据与时间隔离检查通过；任意未来行扰动不改变当前预测；市场背景数据具备完成时间约束；保存加载和中断恢复一致；缺失输入、重复柱及异常柱都有明确处理；开发配置可重放。温启动完整系统单起点 p95 延迟目标不超过 1 秒、冷启动不超过 60 秒，报告实测硬件、窗口与样本数。未达到速度目标时允许交付性能问题清单，不能标为部署验收通过。

**进入最终检验：** 开发主验证合并 MSE 至少相对零收益改善 1%，优于最强单模型及简单融合；至少两个验证季度改善，三个固定种子的合并 MSE 各自均优于零收益；Q2 流程确认也优于零收益和固定最强对照。选择一个主系统后冻结训练、预处理、对照、统计与所有阈值。Q2 的已知性须写进结论，独立证据仍依赖 Q3。

**最终研究成功：** 在同一个三个月保留集、同一组共同起点上，系统须同时满足：

- 相对零收益 MSE 改善至少 1%。
- 优于开发期固定的最强单模型及最强简单融合。
- 对上述三个对照分别计算配对交易日损失差，采用 5 日 moving-block bootstrap、5000 次；检验零假设时使用零中心化分布，单侧检验经 Holm 校正后 `p < 0.05`。
- 至少两个月优于零收益，分别报告开盘、日中、收盘区间以及三种子的稳定性。
- 没有未解释的数据泄漏、缺失预测、选择性丢弃失败或最终检验后修改配置。

同时报告 95% 块置信区间、1 日和 10 日块敏感性、MAE、方向命中、校准及分时段结果。方向指标单独说明零收益的处理，不以它替代主 MSE。用开发残差估算最终集最小可检测改善；若检验力不足，报告区间与探索性证据，不将未显著直接写成没有作用。

其他股票的检验只作预先声明的迁移或次要结果；若扩展为多股票主张，需要另行锁定多重比较规则。不能因为 AAPL 未通过而临时改主标的、主跨度或主指标。

任一正式阶段技术失败应记录并依冻结的恢复规则处理。预算耗尽、全部候选缺乏稳定增量或最终检验失败时，交付完整结果和可运行系统，并标明研究门槛未通过。追加方法需要新的独立未来数据，不反复检验同一 Q3。

**10. 落地系统与论文材料**

落地包提供批量训练入口、历史逐分钟重放入口和单起点预测接口。输入包含股票、完成柱时间、OHLCV 及背景数据；输出包含 12 分钟收益点预测、模型身份、输入截止时间、生成时间、输入完整性状态和所选专家权重。预测区间只有在另设时间校准段并检验覆盖率后才上线，不能把未校准分数标成置信度。

最终必须能演示：加载冻结模型；按时间逐条输入；生成预测；记录故障或缺失；退出后恢复；从保存预测独立重算结果。免费延迟重放与及时未来预测分别命名。

达到预测验收后，再用真实可用时点研究执行、价差、手续费、滑点、换手及盈亏。不以免费延迟数据构造可以在过去时点成交的策略，也不在本计划中下单。预测通过和可交易性通过分开记录。

论文主张由最后的机制与保留检验决定。若得到稳定增量，可围绕“跨股票迁移与状态感知基础模型融合”组织方法、对照、泛化、成本和局限。融合结构本身已有大量先例，投稿前还需对直接相关工作核对新颖性，不能仅凭把现成模型拼接就声称方法创新。实测部署未完成的部分列为未来工作；仿真须写明数据来源、信息时点和假设。
