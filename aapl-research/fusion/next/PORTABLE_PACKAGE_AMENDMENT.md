# CPU 推理包源文件复制修订

2026-11-06，在使用合成行情与小模型的隔离 CPU 集成检查中，256 起点、双进程重放通过后，完整 FP32 包测试在启动时报告引擎身份不匹配。它是准备阶段发现的工程问题，不代表真实研究模型已完成验收。

原因已定位：`scripts/portable_inference_runtime.py` 的包复制适配器按源路径替换 `cpu_run.py`，既替换根目录 `run.py`，也误替换包内 `fusion/next/cloud_assets/cpu_run.py`。后者属于冻结引擎，复制后必须保留原字节，不能使用 FP32 根入口的字节。

修复由独立 `scripts/portable_package_runtime.py` 在未来本地打包进程安装。它仅在目标文件名不是 `run.py` 时保留冻结引擎源文件的字节；根目录入口仍由原 FP32 适配器生成。新修订与独立策略身份一起进入包内 `evidence/`，不修改原引擎、数值适配器、模型、训练、评价或研究门槛。

实际完整推理包仍须解压后，在三个独立进程中依次运行身份核验、示例预测和示例恢复，不能仅以源码检查或文件哈希作为执行通过。当前云端训练不加载本修订。本地等待接收者可通过未来子进程启动钩子接入；安装前核验其精确创建身份与纯等待阶段，保留原钩子和安装收据。
