# CPU/GPU 推理数值一致性技术修订

在 F3 专家搜索结束、主 OOF 尚未开始时，对实际训练完成的选中 xPatch、PatchTST 权重做了本地恢复与数值核验。六份检查点的模型、优化器、覆盖采样器都可以恢复；每份抽取 64 个固定、均匀分布的已知验证起点，CPU BF16 对比原 GPU BF16 预测均未达到原最终入口的严格容差，最大差异约 1.1e-5。失败记录保留，不据此放宽容差。

同一权重、同一组起点改用 FP32 推理，六份检查点的 CPU/CUDA 比较全部通过，最大差异约 1.04e-9。该探针没有训练、修改权重或读取 Q3，也不代表最终融合系统已验收。

修订规则固定如下：训练精度、优化器、已训练权重、采样器、两轮覆盖预算、股票、季度、种子、候选数量和统计门槛均保持原值。后续专家 OOF、融合验证、Q2、条件式 Q3、CPU 重放及推理包使用 FP32 前向推理。适配逻辑由模型目录之外的独立脚本实现，并将适配脚本 SHA、原引擎身份、失败与成功探针哈希写入独立策略收据。

既有专家 10%/30% 的筛选属于 BF16 历史，保留原档位和晋级候选。对两个已完成完整预算的原生专家候选，使用相同完整权重重新生成 FP32 三季度预测，按原始 MSE 重新确定最终排序；原 BF16 预测、选择记录和检查点先归档，不把它们重新标成 FP32。Ridge、LightGBM 原本为 CPU 浮点推理，不改变其结果。该修订用于解决实测数值移植失败，不增加结构、候选或搜索机会。

新预测明确记录 `evaluation_precision=float32` 和独立数值策略身份；旧训练配方继续标明其真实 BF16 训练设置。独立策略不替代原引擎源码身份，二者共同构成可复算入口。推理包必须携带适配脚本、策略收据和显式 FP32 启动入口，不依赖用户额外配置。

必须在恢复后续队列前核验：旧结果归档哈希；新策略身份；原生专家全季度 FP32 重算；CPU/GPU 探针；训练前后配方不变；适配只覆盖预测入口；实际 CPU 包能加载这一策略。最终系统仍须重新通过原开发、Q2、条件式 Q3 和工程验收，不能用专家探针代替。100 小时绝对截止不延长，策略或适配脚本被改动时拒绝继续。

策略首次准备后，在尚无 OOF 季度完成收据时发现并修正 CPU 包入口路径问题：原入口用 `__file__` 推断包根目录，简单模块转发会改变该目录。第二版入口在保持 `run.py` 路径语义的情况下执行原命令，并在加载数值库前限制 CPU 亲和性及线程。实际隔离目录 `--verify-only` 已通过。第一版策略、预测和实现单独归档，第二版有独立身份；训练权重、FP32 前向计算及研究规则均无变化。最初 OOF 的 CPU 工作退出完成后才恢复，部分神经训练检查点继续保留。
