# RTX 5090 性能与训练量修订

修订依据：用户 2026-11-05 提出“极致运用性能，加大数据或者是轮次”，并明确“卡没有上限时间，以达成目标为主”。本修订在首次正式开发评分前生效，替代主计划中的总 24 卡小时、各计算包小时上限，以及仅为满足这些时限而削减宽度和候选数量的规则。原计划文件与原 SHA 保留，后续 GitHub 推送也沿用用户的持续授权。

执行目标是获得可验证的预测增量和可运行系统。吞吐、数据覆盖、训练曲线和实际耗时均须记录。更多计算是否提高预测能力，须由固定验证和最终检验回答；单独的训练损失下降不能证明泛化或充分收敛。

## 已完成的性能证据

初始 batch 64、窗口 240、rank 16 LoRA 的 900.032 秒连续压测已完成，6,833 次更新，约 7.59 更新/秒，峰值显存约 4.2 GiB。缓存、精度、真实适配器、保存恢复和起点隔离检查均通过。初始报告及实际成本另行保存在本地基线目录，不会以新报告替换其历史身份。

随后仅用 2021—2022 年训练数据，比较冻结骨干与 LoRA、FP32 与 BF16、batch 64/128/256/512；512 有显存余量时继续测 1024。每档预热三步，计时 8,192 个样本，包含取样、取窗、传输、反向传播与优化器。不同档位复用模型权重用于测速，损失不能用于比较模型预测质量。

| batch | 冻结 FP32，窗口/秒 | 冻结 BF16，窗口/秒 | LoRA FP32，窗口/秒 | LoRA BF16，窗口/秒 |
| --- | ---: | ---: | ---: | ---: |
| 64 | 1,039 | 953 | 507 | 460 |
| 128 | 1,347 | 1,540 | 762 | 884 |
| 256 | 1,421 | 1,896 | 741 | 1,047 |
| 512 | 924 | 1,205 | 显存不足 | 显存不足 |
| 1024 | 637 | 675 | 不继续扩大 | 不继续扩大 |

两种骨干模式都推荐 batch 256 + BF16。选择规则为“吞吐距最优不超过 5% 时采用最小 batch”，保留显存余量。LoRA 的 batch 512 实际分配超过这张 32 GB 卡容量，失败记录保留。更大的批量也使冻结模式变慢，因此不会仅为提高利用率百分比继续扩大 batch。

batch 256 + BF16 已在 900 秒完整运行中通过全部数值、恢复、起点隔离和资源检查，xPatch/PatchTST 的 BF16 检查也通过。LoRA 去重和云端编排入口完成后，最终代码版本正在重新准入。BF16 的有限性、短程损失与预测偏差须持续通过，不以吞吐取代数值门槛。

## 全量数据与完整训练预算

数据范围保持原计划：AAPL 的未来 12 分钟累计 log 收益、全天共同起点，六只已准入股票 AAPL/MSFT/META/NVDA/AMD/INTC，固定市场背景。每个训练折只使用其合法的更早历史。

| 评分季度 | 训练截止 | 合格去重股票/起点数 | 一个均衡覆盖轮的样本数 |
| --- | --- | ---: | ---: |
| 2025Q1 | 2024-12-30 | 2,264,843 | 2,289,120 |
| 2025Q3 | 2025-06-27 | 2,541,539 | 2,567,280 |
| 2026Q1 | 2025-12-30 | 2,828,590 | 2,859,120 |
| 已知 Q2 前最终拟合 | 2026-03-30 | 2,966,938 | 2,998,200 |

新的覆盖采样器每轮打乱完整股票/交易日的四起点块，保证每个合法窗口至少出现一次。短交易日补足等长日槽；各股票有相同数量的日槽，存在交易日数量差异时，额外日槽逐轮随机轮换。补齐产生的重复样本单列，不能称为新增窗口。这里的去重窗口也不代表统计独立样本；相邻分钟存在重叠，统计检验仍按交易日块处理。

最大历史段决定各模型的固定更新预算。batch 256 时：

| 模型组 | 100% 更新数 | 总样本曝光数 | 训练覆盖要求 |
| --- | ---: | ---: | --- |
| xPatch、PatchTST | 117,118 | 29,982,208 | 至少十个均衡覆盖轮 |
| 冻结融合、LoRA | 146,397 | 37,477,632 | 最多留出 20% 步数作 AAPL 适配，共享阶段仍至少十轮 |

保持原计划 10% → 30% → 100% 连续晋级，首轮就至少覆盖一遍最大合法历史。较早历史段在同一更新预算下会完成更多实际轮次，必须按折报告。AAPL 单股机制沿用配对模型的 batch 与更新数，因此样本复用次数更多；这不增加其去重窗口数。

CPU Ridge/LightGBM 对照改为使用全部合格训练窗口，并用股票/交易日权重保持均衡，不再每天只取 16 个。Ridge 分块累计充分统计量，避免复制两份完整双精度矩阵。

训练持续保存实际覆盖比例、完整覆盖轮数、总曝光数、分段平均训练损失和检查点。正式预算每 1,000 步及晋级边界保存，恢复包括覆盖顺序、重复补齐位置、优化器及随机状态。固定预算不宣称实现了自适应早停；尚未实现的内层早停不会写成已完成。若需更改轮次规则，须在首次正式评分前完成并重新准入，不能看过结果再追加直到成功。

## 计算分配、资源与成本

保留全部预定搜索机会：LightGBM 24、xPatch 16、PatchTST 16、简单融合 12、冻结融合 24、多股票/AAPL 配对 8、LoRA 8；保留三种子与七组机制。更新数由数据量决定，取消原代码的 90/120 秒分配及 1,000～4,000 步裁剪，也取消按旧小时上限自动缩小搜索的逻辑。

LoRA 明确枚举“两种晋级结构 × 两个 rank × 两档学习率”的八个组合。修复原草案在继承晋级结构后出现重复候选的问题，首次评分前验证八个实际配方均不同。

默认单 GPU 作业；CPU 树模型与 GPU 训练并行。冻结骨干可在数值检查通过后用半精度存储表示缓存；LoRA 与随机初始化骨干不复用预训练缓存。缓存键标明实际编码器 FP32 运算、训练头精度、权重、字段、窗口、时间和代码身份。编译或多 GPU 作业并发仍需实测总工期收益。

本地新研究仍合计不超过 18 个逻辑线程，保留原观察服务与 Windows 资源。云端按实际 25 核配额分配；本地单作业 RSS 保持 8 GiB，云端全数据作业 RSS 初始上限 64 GiB，结合实际 90 GiB cgroup 总内存保留余量。可用内存同时检查容器限额和宿主机可用量；至少保留 4 GiB，显存仍不超过设备的 85%。

不设总卡小时和计算包卡小时硬停止。实际 GPU 卡小时、CPU 时间、进程身份、峰值资源、失败与恢复成本继续累计。安装、下载、等待及供应商实际账单仍分别记录。完成最终形状 GPU 与全量 CPU 测量后，对全部折、配置、OOF、种子、机制、最终拟合及部署加入 50% 余量投影；投影用于排程与成本披露，不再用作 24 小时准入门槛。

本轮预算比原先的分钟级试验大得多。仅按短程原始吞吐估算，完整冻结融合约 5.5 小时/拟合、LoRA 约 9.9 小时/拟合，尚未加入缓存、预处理、正式推理和 50% 余量，也不能当作整个研究工期。

第一次完整形状实测所得的全范围规划预览：持续复用冻结缓存的场景约 1,737 小时，全部冻结训练按慢速缓存填充估价的保守投影约 3,758 小时，两者均含 50% 余量，且没有抵扣 CPU/GPU 重叠。前者假设六个缓存图（三个窗口 × 两种字段）保持身份和存储有效，另计首次全量填充；随机骨干和 LoRA 仍按原始执行计价。它们是全部折、种子、机制及交付的排程估计，不是供应商账单或完工承诺。实际可能是数周至数月，最终代码准入完成后再以实际运行持续修正。

## 放行顺序

完成批量测速 → 当前源代码单元测试 → batch 256 精度与 900 秒 GPU 压测、全量 CPU 测量 → 完整范围成本投影 → 一次冻结候选与训练预算 → F3 单模型/OOF → F4 融合与迁移 → F5 LoRA/种子/机制 → F6 固定流程确认 → 条件式 F7 → F8。

云端 `cloud_driver` 会等待已有计量作业结束，归档旧证据和精确源代码，重新完成最终版本的 GPU/CPU 测量与搜索冻结，再启动 F3。任一步失败均保留状态、日志及有效检查点，停止推进；入口有进程锁以防重复启动。当前入口推进到 F3 完成后停止，由后续执行继续 F4，不访问 Q3。

原计划的数据隔离、共同起点、1% 改善、最强对照、种子稳定性、Q2 确认及最终统计条件保持有效。没有新的正式验证结果，2026Q3 数值仍未访问。F5 后若全部候选缺乏稳定增量，按原计划交付负结果和可运行系统；取消租卡时限不改变这个研究停止规则。
