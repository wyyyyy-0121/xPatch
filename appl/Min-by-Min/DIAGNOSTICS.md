# 效果不理想时的处理手册

先确认数据、标签与时间对齐，再改变模型。报告中的诊断是线索，不是自动认定原因。

| 现象 | 检查与行动 | 停止条件 |
|---|---|---|
| 数据问题 | 核对来源凭证、哈希、复权、时区、XNYS 交易日、夏令时和提前收市；逐条检查 origin 后第 1..H 个真实交易柱标签；拒绝插值、缺失聚合柱和跨缺口样本 | 数据未验证时停止真实分钟实验，不输出模型排名 |
| 训练和验证都差 | 比较 train_metrics 与各自最后收盘价基线；检查目标是否过难；调整频率、收益率目标、历史长度、因果特征，再考虑容量 | 所有候选仍输给基线时报告无可靠优势，停止无目的调参 |
| 训练好、验证差 | 排查泄漏和市场变化；减少层数和特征，增加 dropout/weight decay；使用训练内部尾段早停、按时间滚动重训 | 正则化后仍无跨折提升，保留简单模型或基线 |
| 折间差异大 | 检查上涨、下跌、波动率、拆股／分红及交易时段；逐折报告误差与方差 | 不将某一折最好结果当成稳定优势 |
| 只有一个窗口有效 | 增加开发区间滚动折和不同随机种子；先检查缺口导致的样本差异 | 不允许用最终测试区间决定窗口或随机种子 |
| 单模型仅略优于基线 | 必须满足中位 MASE < 1、美元 RMSE 改善至少 2%、至少 3/5 折改善；通过后按归一化收益率误差、折间波动和复杂度选择 | 未通过全部门槛，正式选择最后收盘价，其他结果仅作探索 |

`report.json` 包含训练／验证误差、每个预测步、共同 origin 哈希、训练标签截止时间、MASE 分母、基线提升和诊断标记。`possible_underfit_or_target_data_issue` 无法仅凭误差区分欠拟合、数据问题和难预测目标，需要检查原始证据。`possible_overfit_or_regime_change` 同样不能自动区分过拟合与非平稳。

## 调参顺序

1. 检查 CSV、来源、复权、交易日历、聚合完整性和未来标签。
2. 固定共同 origins、五折边界与 H 柱 purge；所有模型使用相同样本。
3. 改变频率、目标、输入历史与少量因果特征；每次记录配置和验证结果。
4. 调整 Ridge 正则化、减少网络层数／宽度、加强 dropout 和 weight decay。
5. 神经网络使用外层训练集内部的尾部验证与早停。外层验证和最终测试不能用于梯度或早停。
6. 只有训练和验证均提示容量不足、数据检查通过后才增加容量。

当前默认网络最大 20 epochs、patience 3、宽度 32；MLP 隐层 64。CPU 使用 24 threads / 24 DataLoader workers，CUDA 使用 GPU / 0 workers。当前架构为可复现起点，不宣称已完成广泛调参或滚动重训。

## Hybrid 启用与放弃规则

当前实现保持 `not_enabled`。不要把“尚未评估”写成“已经有效”。后续只有同时满足以下条件，才可启用：

- 两个模型的开发区间 out-of-fold 残差来自完全相同 origins；残差相关性低于约 0.8，并检查不同市场阶段。
- 先测试简单加权平均。权重用内层训练／验证确定，外层验证评估，最终测试完全不参与。
- 相对最佳单模型，中位 RMSE 至少改善 2%，至少 3/5 外层折改善；确认收益率误差和稳定性没有明显恶化。
- 检查极端误差与额外复杂度。不能跨折稳定提升就放弃 hybrid，保留最佳简单单模型。

## 测试集纪律

默认命令只运行开发区间验证。确认模型选择后，保存的 `frozen_config.json` 才能传入显式 `--final --freeze ...`。项目级 `results/test_use_ledger.json` 在读取测试预测前登记整个测试时期；失败的最终运行也不自动释放时期，避免反复试验。已有 2014–2022 年附近测试区间曾被读取，属于历史探索／回归，不能再称完全未接触。验证结果和回归冒烟通过均不等于真实分钟实验通过，也不等于具有预测优势。
